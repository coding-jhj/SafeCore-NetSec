# 4일차 명령어 로그

- 날짜: 2026-11-08
- 작업 중 입력한 명령어를 순서대로 기록. 작업 끝나면 4일차_작업계획서.md "결과" 섹션에 요약 반영.
- 범위: 기존 정적 라우팅 기반으로 본사-지사 간 회선 이중화(백업 경로) 구성.

## 1. 백업 회선(시리얼) 케이블 연결 + IP 설정

본사 라우터 NIM 2 슬롯에 NIM-2T 모듈 교체 완료, Serial0/2/0 생성 확인됨. 지사 라우터는 기존 WIC 슬롯(HWIC-2T 추정)의 Serial0/3/0 사용.

### 케이블 연결 (GUI)
- SC-HQ-R1 `Serial0/2/0` ↔ SC-BR-R1 `Serial0/3/0` 시리얼 케이블로 연결

### SC-HQ-R1 (본사 라우터)
```
configure terminal
interface Serial0/2/0
ip address 192.168.80.1 255.255.255.252
no shutdown
exit
```

### SC-BR-R1 (지사 라우터)
```
configure terminal
interface Serial0/3/0
ip address 192.168.80.2 255.255.255.252
no shutdown
exit
```

확인: 양쪽에서 `show ip interface brief`로 Serial0/2/0(본사)·Serial0/3/0(지사) 상태 확인 필요(up/up 또는 DCE 쪽 clock rate 입력 전까지는 down 가능).

## 2. DCE/clock rate 확인

`show controllers serial0/2/0`으로 확인한 결과 본사(SC-HQ-R1) 쪽이 DCE. `show running-config`로 재확인한 결과 `clock rate 2000000`이 NIM-2T 모듈 추가 시 기본값으로 이미 설정되어 있었음 — 별도 clock rate 명령어 입력 불필요.

```
show controllers serial0/2/0
show running-config
```

확인: 양쪽 `show ip interface brief`에서 Serial0/2/0(본사, 192.168.80.1)·Serial0/3/0(지사, 192.168.80.2) 전부 up/up 확인 완료.

## 3. floating static route(백업 경로) — AD 값 250 선정 근거

강사님이 배부한 4일차 작업 계획서에서 예비 경로의 administrative distance(AD)를 250으로 지정. 강사님 문서에는 이유가 따로 적혀있지 않아서, 기술적으로 분석한 근거는 다음과 같음(추론, 강사님이 직접 밝힌 이유 아님).

- AD 값 범위는 1~255. 숫자가 작을수록 더 신뢰하는 경로.
- 255는 "절대 쓰지 않음(unusable)"으로 예약된 특수값 — 이 값을 주면 라우팅 테이블에 아예 안 올라감.
- 주요 라우팅 방식 기본 AD: 직접 연결 0, 정적 라우팅 1, EIGRP 90, OSPF 110, RIP 120, 외부 EIGRP 170, 신뢰 안 함 255.
- 250은 255 바로 아래 숫자 — 어떤 라우팅 방식보다도 확실히 후순위로 미루면서, 그래도 255(완전 비활성)는 아니라서 "최후의 수단"으로는 쓸 수 있게 살려둔 값으로 해석됨.


### SC-HQ-R1 (본사 라우터)
```
configure terminal
ip route 192.168.60.0 255.255.255.0 192.168.80.2 250
exit
```

### SC-BR-R1 (지사 라우터)
```
configure terminal
ip route 192.168.10.0 255.255.255.0 192.168.80.1 250
ip route 192.168.20.0 255.255.255.0 192.168.80.1 250
ip route 192.168.30.0 255.255.255.0 192.168.80.1 250
ip route 192.168.40.0 255.255.255.0 192.168.80.1 250
ip route 192.168.50.0 255.255.255.0 192.168.80.1 250
exit
```

확인: `show running-config | include ip route`로 양쪽 다 기존 경로(AD 1)와 백업 경로(AD 250)가 함께 설정 파일에 들어가 있는 것 확인 완료. `show ip route static`에는 AD가 더 낮은 기존 경로만 표시되는 게 정상(백업 경로는 기존 회선이 살아있는 동안은 대기 상태).

## 4. 장애 테스트 (failover 확인)

지사 PC에서 본사(서버팜 게이트웨이)로 지속 핑을 보내는 상태에서 본사 기존 WAN 포트를 강제로 내려서, 백업 경로로 자동 전환되는지 확인.

### 지사 PC 명령 프롬프트
```
ping 192.168.50.1 -t
```
결과: 패킷 1개만 유실(Request timed out) 후 바로 Reply 재개. 전체 12개 중 11개 성공(9% loss) — 전환 순간 한 번만 끊기고 바로 복구됨.

### SC-HQ-R1 (본사 라우터) - 기존 회선 차단
```
configure terminal
interface GigabitEthernet0/1/3
shutdown
exit
```

확인(차단 중): 양쪽 `show ip route static`에서 기존 경로(AD 1) 대신 백업 경로가 올라온 것 확인.
- 본사: `S    192.168.60.0/24 [250/0] via 192.168.80.2`
- 지사: `S    192.168.10~50.0/24 [250/0] via 192.168.80.1` (5줄 전부)

### SC-HQ-R1 (본사 라우터) - 기존 회선 복구
```
configure terminal
interface GigabitEthernet0/1/3
no shutdown
exit
```

확인(복구 후): 본사는 `show ip route static`에서 즉시 `[1/0] via 192.168.70.2`로 복귀 확인. 지사는 처음엔 `[250/0]`이 그대로 남아있었는데, 원인은 ARP 미갱신 — `ping 192.168.70.1`로 ARP를 다시 학습시키니(첫 패킷만 실패, 이후 성공) `show ip route static`에서 지사도 `[1/0] via 192.168.70.1`로 5줄 전부 복귀 확인.

**결론: 기존 회선 장애 시 백업 경로(시리얼, AD 250)로 자동 전환되고, 기존 회선 복구 시 다시 기존 경로로 돌아오는 것까지 전체 사이클 확인 완료.**

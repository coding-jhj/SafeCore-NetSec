## 1. 본사 라우터(SC-HQ-R1) 부서 VLAN+SVI 설정

NIM-ES2-4 모듈 포트(Gi0/1/0~2)는 `ip address`를 바로 못 받아서, VLAN 생성 후 SVI(interface vlan X)에 IP를 넣는 방식으로 진행.

### 기술지원팀(본사) - VLAN 30
```
interface GigabitEthernet0/1/0
switchport mode access
switchport access vlan 30
exit
interface vlan 30
ip address 192.168.30.1 255.255.255.0
no shutdown
exit
```

### 경영지원팀 - VLAN 40
```
interface GigabitEthernet0/1/1
switchport mode access
switchport access vlan 40
exit
interface vlan 40
ip address 192.168.40.1 255.255.255.0
no shutdown
exit
```

### 서버팜 - VLAN 50
```
interface GigabitEthernet0/1/2
switchport mode access
switchport access vlan 50
exit
interface vlan 50
ip address 192.168.50.1 255.255.255.0
no shutdown
exit
```

확인: `show ip interface brief`로 연구개발(.10)/QA(.20)/기술지원본사(.30)/경영지원(.40)/서버팜(.50) 전부 up/up 확인 완료.

## 2. 장비 호스트네임 설정

```
hostname SC-BR-R1       (지사 라우터)
hostname SC-SW-RND       (연구개발팀 스위치)
hostname SC-SW-QA        (품질보증팀 스위치)
hostname SC-SW-TS        (기술지원팀 본사 스위치)
hostname SC-SW-ADM       (경영지원팀 스위치)
hostname SC-SW-SRV       (서버팜 스위치)
hostname SC-SW-TSBR      (기술지원팀 지사 스위치)
```

## 3. 본사-지사 WAN 링크

- 물리 연결: 본사 ISR4331(SC-HQ-R1) GigabitEthernet0/0/2 ↔ 지사 2901(SC-BR-R1) GigabitEthernet0/1 (Automatically Choose Connection Type 케이블)
  - 실제로는 Gig0/1/3에 연결됨 (CDP로 확인) → NIM 모듈 포트라 VLAN+SVI 방식으로 진행
- 대역: VLAN 70, 192.168.70.0/24 (기존 부서 대역 체계와 통일, /24 유지)

### SC-HQ-R1
```
interface GigabitEthernet0/1/3
switchport mode access
switchport access vlan 70
exit
interface vlan 70
ip address 192.168.70.1 255.255.255.0
no shutdown
exit
```

### SC-BR-R1
```
interface GigabitEthernet0/1
ip address 192.168.70.2 255.255.255.0
no shutdown
exit
```

확인: `show cdp neighbors`로 SC-HQ-R1 Gig0/1/3 ↔ SC-BR-R1 Gig0/1 연결 확인.

## 4. 지사 라우터(SC-BR-R1) 내부 LAN 게이트웨이

기술지원팀(지사), VLAN 60, 192.168.60.0/24. SC-BR-R1 Gi0/0은 일반 라우티드 포트라 바로 IP 할당.

```
interface GigabitEthernet0/0
ip address 192.168.60.1 255.255.255.0
no shutdown
exit
```

## 5. 정적 라우팅

### SC-HQ-R1 (지사 네트워크로 가는 길)
```
ip route 192.168.60.0 255.255.255.0 192.168.70.2
```

### SC-BR-R1 (본사 5개 네트워크로 가는 길)
```
ip route 192.168.10.0 255.255.255.0 192.168.70.1
ip route 192.168.20.0 255.255.255.0 192.168.70.1
ip route 192.168.30.0 255.255.255.0 192.168.70.1
ip route 192.168.40.0 255.255.255.0 192.168.70.1
ip route 192.168.50.0 255.255.255.0 192.168.70.1
```

확인: `SC-BR-R1#ping 192.168.10.1` 성공.

## 6. 기타

- `no ip domain-lookup` : 오타 입력 시 DNS 조회로 지연되는 것 방지. 전 장비(SC-HQ-R1, SC-BR-R1, 스위치 6개)에 적용 요청함.

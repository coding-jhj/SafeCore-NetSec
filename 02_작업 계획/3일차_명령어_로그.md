## 1. 본사 라우터(SC-HQ-R1) 부서 VLAN+SVI 설정

NIM-ES2-4 모듈 포트(Gi0/1/0~2)는 `ip address`를 바로 못 받아서, VLAN 생성 후 SVI(interface vlan X)에 IP를 넣는 방식으로 진행.

### 기술지원팀(본사) - VLAN 30
```
interface GigabitEthernet0/1/0
switchport mode access
switchport access vlan 30
exit
interface vlan 30
ip address 192.168.30.1 255.255.255.0
no shutdown
exit
```

### 경영지원팀 - VLAN 40
```
interface GigabitEthernet0/1/1
switchport mode access
switchport access vlan 40
exit
interface vlan 40
ip address 192.168.40.1 255.255.255.0
no shutdown
exit
```

### 서버팜 - VLAN 50
```
interface GigabitEthernet0/1/2
switchport mode access
switchport access vlan 50
exit
interface vlan 50
ip address 192.168.50.1 255.255.255.0
no shutdown
exit
```

확인: `show ip interface brief`로 연구개발(.10)/QA(.20)/기술지원본사(.30)/경영지원(.40)/서버팜(.50) 전부 up/up 확인 완료.

## 3. 본사-지사 WAN 링크

- 물리 연결: 본사 ISR4331(SC-HQ-R1) GigabitEthernet0/0/2 ↔ 지사 2901(SC-BR-R1) GigabitEthernet0/1 (Automatically Choose Connection Type 케이블)
  - 실제로는 Gig0/1/3에 연결됨 (CDP로 확인) → NIM 모듈 포트라 VLAN+SVI 방식으로 진행
- 대역: VLAN 70, 192.168.70.0/24 (기존 부서 대역 체계와 통일, /24 유지)

확인: `show cdp neighbors`로 SC-HQ-R1 Gig0/1/3 ↔ SC-BR-R1 Gig0/1 연결 확인.

## 4. 지사 라우터(SC-BR-R1) 내부 LAN 게이트웨이

기술지원팀(지사), VLAN 60, 192.168.60.0/24. SC-BR-R1 Gi0/0은 일반 라우티드 포트라 바로 IP 할당.

## 8. 스위치 6개 - VLAN 생성 + 포트 할당

connected 포트 전체(PC 포트 + 업링크 포트)를 interface range로 한 번에 할당. `switchport access vlan X` 입력 시 VLAN 자동 생성됨.

```
SC-SW-RND: interface range fastEthernet 0/1-15 → switchport mode access → switchport access vlan 10
SC-SW-QA:  interface range fastEthernet 0/1-7  → switchport mode access → switchport access vlan 20
SC-SW-TS:  interface range fastEthernet 0/1-7  → switchport mode access → switchport access vlan 30
SC-SW-ADM: interface range fastEthernet 0/1-9  → switchport mode access → switchport access vlan 40
SC-SW-SRV: interface range fastEthernet 0/1-5  → switchport mode access → switchport access vlan 50
SC-SW-TSBR: interface range fastEthernet 0/1-9 → switchport mode access → switchport access vlan 60
```

(SC-SW-QA는 처음에 범위를 0/1-17로 잘못 입력해서, `interface range fastEthernet 0/8-17` → `no switchport access vlan`으로 되돌려서 수정함.)

## 12. 안 쓰는 포트/VLAN shutdown (보안 강화)

각 스위치의 connected 범위 밖 포트(안 쓰는 포트) + Gig0/1-2를 전부 shutdown.

```
SC-SW-RND:  interface range fastEthernet 0/16-24 → shutdown / interface range gigabitEthernet 0/1-2 → shutdown
SC-SW-QA:   interface range fastEthernet 0/8-24  → shutdown / interface range gigabitEthernet 0/1-2 → shutdown
SC-SW-TS:   interface range fastEthernet 0/8-24  → shutdown / interface range gigabitEthernet 0/1-2 → shutdown
SC-SW-ADM:  interface range fastEthernet 0/10-24 → shutdown / interface range gigabitEthernet 0/1-2 → shutdown
SC-SW-SRV:  interface range fastEthernet 0/6-24  → shutdown / interface range gigabitEthernet 0/1-2 → shutdown
SC-SW-TSBR: interface range fastEthernet 0/10-24 → shutdown / interface range gigabitEthernet 0/1-2 → shutdown
```

(SC-SW-SRV에서 실수로 TSBR용 범위를 입력해서 Fa0/6-9가 빠짐 → `interface range fastEthernet 0/6-9` → `shutdown`으로 추가 수정함.)

적용 후 8대 전부 `copy running-config startup-config`로 재저장.

## 13. 수업 과제 - 라우터-스위치 트렁크 재구성 (메인 포트폴리오와 별개, 과정 기록용)

본사 라우터는 SC-SW-RND에만 연결 유지. SC-SW-QA/TS/ADM/SRV는 라우터 연결을 끊고, RND를 기준으로 체인(사슬) 구조로 재연결: RND-QA-TS-ADM-SRV.

물리 연결 확인 (`show cdp neighbors`):

| 연결 | 포트 |
|---|---|
| SC-HQ-R1 Gi0/0/0 ↔ SC-SW-RND | Fa0/1 |
| SC-SW-RND ↔ SC-SW-QA | Fa0/16 ↔ Fa0/1 |
| SC-SW-QA ↔ SC-SW-TS | Fa0/8 ↔ Fa0/4 |
| SC-SW-TS ↔ SC-SW-ADM | Fa0/8 ↔ Fa0/4 |
| SC-SW-ADM ↔ SC-SW-SRV | Fa0/10 ↔ Fa0/5 |

### SC-HQ-R1 (Router-on-a-Stick 서브인터페이스로 전환)

```
interface GigabitEthernet0/0/0
no ip address
no shutdown
exit
interface GigabitEthernet0/0/1
no ip address
shutdown
exit
no interface Vlan30
no interface Vlan40
no interface Vlan50
interface GigabitEthernet0/0/0.10
encapsulation dot1Q 10
ip address 192.168.10.1 255.255.255.0
exit
interface GigabitEthernet0/0/0.20
encapsulation dot1Q 20
ip address 192.168.20.1 255.255.255.0
exit
interface GigabitEthernet0/0/0.30
encapsulation dot1Q 30
ip address 192.168.30.1 255.255.255.0
exit
interface GigabitEthernet0/0/0.40
encapsulation dot1Q 40
ip address 192.168.40.1 255.255.255.0
exit
interface GigabitEthernet0/0/0.50
encapsulation dot1Q 50
ip address 192.168.50.1 255.255.255.0
exit
interface GigabitEthernet0/1/0
shutdown
exit
interface GigabitEthernet0/1/1
shutdown
exit
interface GigabitEthernet0/1/2
shutdown
end
```

(주의: Gi0/0/1 IP 제거 및 VLAN30/40/50 SVI 제거를 서브인터페이스 설정보다 먼저 해야 함. 나중에 하면 "overlaps with" 에러 발생.)

### 스위치 5개 - VTP(서버/클라이언트) + 트렁크

2960 시리즈는 802.1Q만 지원해서 `switchport trunk encapsulation dot1q` 명령어 자체가 없음(Invalid input 에러). `switchport mode trunk`만 입력하면 됨.

**SC-SW-RND (VTP 서버)**
```
vtp domain SAFECORE
vtp mode server
vlan 20
name QA
exit
vlan 30
name TechSupport_HQ
exit
vlan 40
name Admin
exit
vlan 50
name ServerFarm
exit
interface fastEthernet 0/1
switchport mode trunk
exit
interface fastEthernet 0/16
switchport mode trunk
end
```

**SC-SW-QA / SC-SW-TS / SC-SW-ADM / SC-SW-SRV (VTP 클라이언트)**
```
vtp domain SAFECORE
vtp mode client
interface fastEthernet 0/X (QA는 0/1, TS/ADM은 0/4)
switchport mode trunk
exit
interface fastEthernet 0/Y (QA는 0/8, TS는 0/8, ADM은 0/10, SRV는 0/5만)
switchport mode trunk
end
```

## 14. 수업 과제 - 트렁크/VTP 적용 결과 검증

### 본사 라우터 서브인터페이스 확인
```
show ip interface brief
```
결과: Gi0/0/0.10~.50 전부 up/up, Gi0/0/1·Gi0/1/0~2는 administratively down, Gi0/1/3(WAN)·Vlan70은 그대로 up/up 유지됨. 정상 적용 확인.

### 스위치 5개 VTP/트렁크 상태 확인
```
show vtp status
show interfaces trunk
```
결과: SC-SW-RND(서버)와 SC-SW-QA/TS/ADM/SRV(클라이언트) 5대 전부 MD5 digest 완전히 일치(VTP 동기화 정상), Fa0/1·Fa0/16(RND), Fa0/1·Fa0/8(QA), Fa0/4·Fa0/8(TS), Fa0/4·Fa0/10(ADM), Fa0/5(SRV) 전부 802.1q trunking 상태. VLAN 1,10,20,30,40,50 전체 전파 확인.

### 부서 간 ping 테스트 (체인 양 끝단)
```
서버팜(VLAN50) PC → ping 192.168.10.11 (연구개발팀 PC)
```
결과: Reply 4/4 성공 (0% loss) — 체인 구조(RND-QA-TS-ADM-SRV) 전체를 거쳐 통신 정상 확인.

캡처 8종(라우터 서브인터페이스, CDP, 스위치 5대 VTP+트렁크, ping) 전부 확보 완료 — 3일차_작업계획서.md 결과 섹션용.

## 15. 수업 과제 되돌리기 — 원래 설계(부서별 라우터 직결 + VLAN/SVI)로 복원

트렁크 구조는 캡처만 남기고, 메인 포트폴리오 최종 상태는 원래 설계로 되돌림.

### 물리 재배선 (GUI)
- 제거: RND Fa0/16↔QA Fa0/1, QA Fa0/8↔TS Fa0/4, TS Fa0/8↔ADM Fa0/4, ADM Fa0/10↔SRV Fa0/5
- 복원: QA Fa0/1→SC-HQ-R1 Gi0/0/1, TS Fa0/4→SC-HQ-R1 Gi0/1/0, ADM Fa0/4→SC-HQ-R1 Gi0/1/1, SRV Fa0/5→SC-HQ-R1 Gi0/1/2 (RND Fa0/1↔Gi0/0/0은 안 건드림)

### SC-HQ-R1 원복
```
interface GigabitEthernet0/0/0
no ip address
exit
no interface GigabitEthernet0/0/0.10
no interface GigabitEthernet0/0/0.20
no interface GigabitEthernet0/0/0.30
no interface GigabitEthernet0/0/0.40
no interface GigabitEthernet0/0/0.50
interface GigabitEthernet0/0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit
interface GigabitEthernet0/0/1
ip address 192.168.20.1 255.255.255.0
no shutdown
exit
interface GigabitEthernet0/1/0
switchport access vlan 30
no shutdown
exit
interface GigabitEthernet0/1/1
switchport access vlan 40
no shutdown
exit
interface GigabitEthernet0/1/2
switchport access vlan 50
no shutdown
exit
interface Vlan30
ip address 192.168.30.1 255.255.255.0
no shutdown
exit
interface Vlan40
ip address 192.168.40.1 255.255.255.0
no shutdown
exit
interface Vlan50
ip address 192.168.50.1 255.255.255.0
no shutdown
exit
```
확인: `show ip interface brief`로 Gi0/0/0(.10)·Gi0/0/1(.20) 직접 IP, Gi0/1/0~2 up/up, Vlan30/40/50 SVI up/up, Gi0/1/3·Vlan70(WAN) 그대로 유지 확인 완료.

### 스위치 5개 원복 (VTP transparent 전환 → 트렁크 포트 access 복귀 → RND만 VLAN 정리)

```
SC-SW-RND:
interface fastEthernet 0/1
switchport mode access
switchport access vlan 10
exit
interface fastEthernet 0/16
switchport mode access
shutdown
exit
vtp mode transparent
no vlan 20
no vlan 30
no vlan 40
no vlan 50

SC-SW-QA:
vtp mode transparent
interface fastEthernet 0/1
switchport mode access
switchport access vlan 20
exit
interface fastEthernet 0/8
switchport mode access
shutdown

SC-SW-TS:
vtp mode transparent
interface fastEthernet 0/4
switchport mode access
switchport access vlan 30
exit
interface fastEthernet 0/8
switchport mode access
shutdown

SC-SW-ADM:
vtp mode transparent
interface fastEthernet 0/4
switchport mode access
switchport access vlan 40
exit
interface fastEthernet 0/10
switchport mode access
shutdown

SC-SW-SRV:
vtp mode transparent
interface fastEthernet 0/5
switchport mode access
switchport access vlan 50
```

(주의: RND에서 `vtp mode transparent`를 VLAN 삭제보다 먼저 해야 QA/TS/ADM/SRV의 자기 VLAN이 같이 삭제되는 걸 막을 수 있음.)

확인(RND): `show vlan brief`에서 VLAN10(RnD)에 Fa0/1~15만 남고 VLAN20/30/40/50 없음, Fa0/16은 VLAN1(default)로 복귀. `show interfaces trunk` 결과 없음(트렁크 완전 제거) — 정상 확인.

확인(QA/TS/ADM/SRV): QA는 VLAN20에 Fa0/1~7, TS는 VLAN30에 Fa0/1~7, ADM은 VLAN40에 Fa0/1~9만 남고 각 복귀 포트(Fa0/8, Fa0/8, Fa0/10)는 VLAN1로 정상 복귀. SRV는 VLAN50에 Fa0/1~5(원래 업링크라 복귀 대상 없음). 4대 전부 `show interfaces trunk` 결과 없음 — 정상 확인.

8대 전부 `write memory`로 저장 완료. 스위치 5대 전체 원복 검증 완료.

### 되돌리기 후 ping 재검증
```
연구개발팀(VLAN10) PC → ping 192.168.50.11
```
1차 시도: 4개 중 2개 timeout, 2개 성공(50% loss) — 포트 설정 변경 직후 ARP 재조회 + STP 포워딩 전환 지연으로 인한 일시적 현상으로 판단, 재시도 요청함.

2차 시도(재검증): Reply 4/4 성공 (0% loss) — 되돌리기 최종 검증 완료. 부서별 라우터 직결 + VLAN/SVI 구조로 정상 복원됨.

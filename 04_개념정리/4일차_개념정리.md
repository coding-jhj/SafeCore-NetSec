# 4일차 개념 정리: 회선 이중화와 floating static route

## 1. 이 단계에서 한 일
- 본사 라우터에 NIM-2T 시리얼 모듈을 추가하고, 본사 Serial0/2/0과 지사 Serial0/3/0을 시리얼 케이블로 연결했다(192.168.80.0/30).
- 기존 정적 경로(AD 1)는 두고, 같은 목적지에 AD 250인 예비 정적 경로를 추가했다.
- 주 회선(본사 Gi0/1/3)을 끊어서 예비로 전환되는지, 복구 시 원래대로 돌아오는지 확인했다.
- 작업 기록: `02_작업 계획/4일차_작업계획서.md`, `05_명령어_로그/4일차_명령어_로그.md`

## 2. 개념

### 회선 이중화(Redundancy)
- 단일 장애점(하나가 고장 나면 전체가 멈추는 지점)을 없애려고 경로를 두 개 두는 것이다. 보안 3요소 중 가용성에 해당한다.
- 요구사항에서 지사 기술지원팀은 본사 티켓 시스템과 파일 서버를 쓰므로, 본사-지사 회선이 끊기면 지사 업무가 멈춘다. 이것을 막는 것이 이 작업의 이유다.
- 서로 다른 매체(이더넷과 시리얼)를 쓰면 같은 원인으로 둘 다 끊길 가능성이 줄어든다.

### 시리얼 링크: DCE, DTE, clock rate
- 시리얼 WAN 구간은 한쪽(DCE)이 박자(clock)를 제공하고 다른 쪽(DTE)이 따라간다. DCE 쪽에 `clock rate`가 있어야 링크가 올라온다.
- 우리 구성에서는 `show controllers`로 본사가 DCE임을 확인했고, NIM-2T 모듈을 추가하면 clock rate 2000000이 기본으로 들어 있어서 따로 입력하지 않았다.
- Cisco 시리얼의 기본 캡슐화는 HDLC다.

### /30 point-to-point
- 두 장비만 연결하는 구간은 주소가 2개만 필요하다. /30은 호스트 주소가 2개라서 딱 맞고, 부서 /24와 대역을 구분하는 효과도 있다.
- 우리는 192.168.80.0/30을 썼다(본사 .1, 지사 .2).

### Administrative Distance(AD)
- 서로 다른 출처(정적, RIP, OSPF 등)가 같은 목적지를 알려줄 때 어느 쪽을 믿을지 정하는 신뢰도 값이다. 작을수록 신뢰한다. 범위는 0에서 255이고 255는 사용하지 않음을 뜻한다.

| 출처 | 기본 AD |
|------|---------|
| 직접 연결 | 0 |
| 정적 경로 | 1 |
| EIGRP | 90 |
| OSPF | 110 |
| RIP | 120 |
| 신뢰 안 함 | 255 |

### 라우팅 테이블의 경로 선택 순서
1. 가장 긴 프리픽스가 일치하는 경로(더 구체적인 경로)가 우선한다.
2. 프리픽스가 같으면 AD가 낮은 출처가 우선한다.
3. 같은 출처 안에서는 metric이 낮은 경로가 우선한다.

### Floating static route
- 평소에는 라우팅 테이블에 올라오지 않고 대기하다가, 더 신뢰도 높은 경로가 사라지면 올라오는 정적 경로다. AD를 기본 1보다 높게 줘서 만든다.
- 우리는 AD 250을 썼다. 다른 어떤 라우팅 방식보다도 후순위로 두면서 255(사용 안 함)는 피한 값이다. 강사 자료에 250이 지정되어 있었고, 이유는 따로 적혀 있지 않아서 로그의 설명은 우리가 분석한 추정이다.

### 장애 전환이 일어난 원리
- 주 회선 포트를 shutdown하면 그 인터페이스를 next-hop으로 하는 AD 1 경로가 테이블에서 사라진다. 그러면 AD 250 경로가 올라와서 시리얼 선으로 트래픽이 간다.
- 복구하면 AD 1 경로가 다시 올라와서 우선한다.
- 실습에서는 지속 ping 중 패킷 1개가 유실된 뒤 복구되었다.

### 복구 시 관찰한 현상
- 본사는 복구 직후 바로 원래 경로로 돌아왔지만, 지사는 한동안 `[250/0]` 경로가 남아 있었다. 로그에서는 ARP 정보가 갱신되지 않은 것이 원인으로 파악했고, `ping 192.168.70.1`로 ARP를 다시 학습시키자 원래 경로로 돌아왔다.

### 정적 라우팅 이중화의 한계
- 정적 경로는 "해당 인터페이스가 down"일 때만 사라진다. 우리 실습처럼 장비가 직접 연결되어 있으면 상대가 끊겼을 때 내 인터페이스도 내려가서 잘 동작한다.
- 하지만 중간에 스위치나 ISP 구간이 있어서 내 인터페이스는 up인데 상대까지 도달이 안 되는 경우에는 정적 경로가 장애를 감지하지 못한다. 이 경우 IP SLA와 track으로 도달성을 검사하거나 동적 라우팅을 써야 한다. IP SLA는 아직 적용하지 않았다.

## 3. 우리 프로젝트의 값
- 주 회선: 본사 Gi0/1/3(VLAN 70, 192.168.70.1) 와 지사 Gi0/1(192.168.70.2)
- 백업 회선: 본사 Serial0/2/0(192.168.80.1) 와 지사 Serial0/3/0(192.168.80.2)
- 예비 경로: 본사 1줄(192.168.60.0/24 via 192.168.80.2, AD 250), 지사 5줄(192.168.10, 20, 30, 40, 50 대역 via 192.168.80.1, AD 250)

## 4. 면접 예상 질문과 답변 요지
- 왜 회선을 이중화했나: 지사가 본사 서버를 쓰므로 회선 하나가 끊기면 업무가 멈춘다. 가용성을 위해 두 번째 회선을 뒀다.
- 왜 두 번째 회선을 시리얼로 했나: 이더넷과 다른 매체를 써서 같은 원인으로 둘 다 끊길 가능성을 낮추고, 현실적인 이중화에 가깝기 때문이다.
- floating static route가 무엇인가: AD를 높여서 평소엔 숨어 있다가 주 경로가 사라질 때만 쓰이는 정적 경로다.
- AD가 무엇인가: 서로 다른 출처의 경로 중 어느 쪽을 믿을지 정하는 값이다.
- 이 방식의 한계는: 인터페이스가 down일 때만 전환된다. 중간 구간 장애는 못 잡아서 IP SLA나 동적 라우팅이 필요하다.

## 5. 보안 요소와의 연결
- 가용성: 주 회선 장애에도 본사-지사 통신이 유지된다. 요구사항의 포털 가용성과는 대상이 다르지만(포털은 외부 공개 서비스) 같은 가용성 원칙이다.

## 2. 개념

### VLAN
- 물리적으로 같은 스위치에 있어도 논리적으로 네트워크를 나누는 기술이다. VLAN마다 브로드캐스트 도메인이 따로 생긴다.
- VLAN을 나누면 서로 다른 VLAN끼리는 라우터(L3)를 거쳐야만 통신한다. 그 지점이 통제 지점이 된다.

### 액세스 포트와 트렁크 포트
- 액세스 포트: 하나의 VLAN에만 속하며 PC가 연결되는 포트. 프레임에 VLAN 태그가 붙지 않는다.
- 트렁크 포트: 여러 VLAN의 트래픽을 한 선으로 전달하는 포트. IEEE 802.1Q 태그(VLAN ID, 12비트로 1부터 4094)를 붙여서 구분한다.
- 네이티브 VLAN은 트렁크에서 태그 없이 전달되는 VLAN이다. 설정이 어긋나면 문제가 생기고, 보안상 VLAN 호핑 공격과도 관련되어 있다(후속 하드닝에서 다룰 항목).
- Catalyst 2960은 802.1Q만 지원해서 `switchport trunk encapsulation dot1q` 명령이 없다. 실습에서 이 명령이 에러 나는 것으로 확인했다.

### VLAN 사이 통신(Inter-VLAN routing)을 만드는 세 가지 방식

| 방식 | 구조 | 특징 |
|------|------|------|
| 전용 포트 | 부서마다 라우터 포트 하나씩 | 단순하고 병목이 없지만 포트 수가 필요 |
| Router-on-a-Stick | 라우터 포트 하나에 트렁크 + 서브인터페이스 | 포트는 절약되지만 한 선에 모든 부서 트래픽이 몰림 |
| SVI(L3 스위치) | 스위치 안의 가상 인터페이스에 IP | 라우팅을 스위치 내부에서 처리 |

- 우리 본사 라우터는 부서별 전용 포트 구조다. 온보드 포트(연구개발, QA)는 포트에 직접 IP를 주고, NIM-ES2-4 모듈 포트는 스위치 포트 성격이라 `no switchport`가 안 되어서(실습에서 `% Incomplete command`) VLAN을 만든 뒤 SVI에 IP를 줬다.
- 일반적으로 SVI는 해당 VLAN에 활성 포트가 하나 이상 있어야 up 상태가 된다.
- Router-on-a-Stick과 트렁크, VTP는 수업 과제로 구성하고 검증한 뒤 메인 설계에서 뺐다. 이유는 부서별 전용 포트 구조가 이미 실제 연결과 맞고, 한 선에 몰리는 병목이 없기 때문이다.

### VTP
- VLAN 정보를 스위치 사이에 자동으로 전파하는 프로토콜이다. 모드는 서버, 클라이언트, 트랜스패런트가 있고, 같은 도메인 이름 안에서 동작한다.
- 서버에서 VLAN을 만들면 클라이언트가 따라온다. 편리하지만, revision 번호가 더 높은 스위치가 연결되면 기존 VLAN 정보를 덮어쓸 수 있어서 운영 사고와 보안 위험이 된다.
- 우리 실습에서는 도메인 SAFECORE, RND를 서버, 나머지를 클라이언트로 두고 VLAN 전파를 확인한 뒤, 트랜스패런트로 되돌렸다.

### 정적 라우팅
- 관리자가 경로를 직접 적는 방식이다. "이 목적지 대역은 이 next-hop으로 보내라".
- 장점은 단순하고 라우터 부하가 없고 예측 가능하다는 점이다. 단점은 네트워크가 늘 때마다 사람이 추가해야 하고, 장애를 스스로 감지하지 못한다는 점이다. 5일차에서 이 단점을 RIP으로 풀었다.
- 라우터는 패킷의 목적지를 라우팅 테이블에서 가장 길게 일치하는 경로(longest prefix match)로 찾아서 next-hop으로 보낸다.
- 라우팅 테이블의 `C`는 직접 연결된 대역, `L`은 라우터 자신의 인터페이스 주소(/32), `S`는 정적 경로다.

### ARP
- IP 주소로 MAC 주소를 알아내는 프로토콜이다. 같은 네트워크 안에서 프레임을 보내려면 상대 MAC이 필요하다.
- 처음 ping의 첫 패킷이 유실되는 경우가 있는데, ARP 학습 때문인 경우가 많다.

### 장비 관리 접속과 비밀번호
- 텔넷은 원격 CLI 접속이지만 평문으로 전송되어 비밀번호가 엿보일 수 있다. 실무에서는 SSH를 쓴다. 우리는 학습 단계라 텔넷을 썼고, SSH 전환은 후속 하드닝 항목이다.
- `enable secret`은 해시로 저장되고, `enable password`와 line의 `password`는 설정 파일에 평문으로 보인다. `service password-encryption`으로 간단히 가릴 수 있지만 강한 암호화는 아니다.
- 미사용 포트를 shutdown하는 이유는 누군가 몰래 장비를 꽂아도 통신이 안 되게 하려는 것이다.
- CDP는 이웃 장비 정보를 알려주는 프로토콜이다. 연결 확인에 편리하지만 정보 노출 위험이 있어서, 외부와 닿는 포트에서는 끄는 것이 보통이다.
- `no ip domain-lookup`은 잘못 입력한 명령을 도메인 이름으로 착각해서 기다리는 일을 막는다.

## 4. 면접 예상 질문과 답변 요지
- VLAN이 왜 필요한가: 같은 물리 장비에서 네트워크를 논리적으로 나눠서 브로드캐스트를 줄이고 부서 간 통신을 라우터에서 통제하기 위해서다.
- 액세스와 트렁크의 차이: 액세스는 한 VLAN, 트렁크는 여러 VLAN을 802.1Q 태그로 구분해 전달한다.
- Router-on-a-Stick과 SVI의 차이: 앞은 라우터의 서브인터페이스로 한 선에 몰아서 처리하고, 뒤는 스위치 안의 가상 인터페이스로 처리한다.
- 왜 메인 설계를 전용 포트로 했나: 실제 연결 구조가 부서별 전용 포트였고, 병목이 없고 단순해서다. Router-on-a-Stick은 수업 과제로 해보고 비교했다.
- VTP의 위험은: revision 번호가 높은 스위치를 연결하면 VLAN 정보가 덮어써질 수 있다.
- 텔넷의 문제와 개선: 평문 전송이라 엿볼 수 있어서 SSH로 바꿔야 하고, 접속 가능한 주소를 ACL로 제한해야 한다.

## 5. 보안 요소와의 연결
- VLAN 분리와 미사용 포트 shutdown, 접속 비밀번호는 장비 설정 무결성(라우터와 스위치 무단 접속 방지)과 기밀성의 기반이다. 평문 텔넷은 이 요구에 대한 현재의 약점으로, 개선 항목이다.

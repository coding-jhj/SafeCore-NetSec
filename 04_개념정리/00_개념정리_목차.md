# 개념 정리 목차

- 목적: 프로젝트에서 한 작업을 면접에서 개념과 함께 설명할 수 있도록, 일차별로 "무엇이고, 왜 썼고, 우리 구성에서 어떻게 썼는지"를 정리한다.
- 명령어 자체는 `05_명령어_로그/` 폴더의 일차별 명령어 로그에 있고, 이 폴더는 개념과 면접 답변 요지만 다룬다.
- 작업이 진행될 때마다 해당 일차 문서를 갱신한다.

## 보안 3요소와 이 프로젝트의 보안 요구

보안의 기본 목표는 세 가지다.

| 요소 | 뜻 |
|------|-----|
| 기밀성(Confidentiality) | 허가받은 사람만 정보를 볼 수 있다 |
| 무결성(Integrity) | 정보나 설정이 허가 없이 바뀌지 않는다 |
| 가용성(Availability) | 필요할 때 서비스를 쓸 수 있다 |

`01_요구사항/프로젝트_계획서.md`의 보안 요구와 대응은 다음과 같다.

| 보안 요구 | 요소 |
|-----------|------|
| 소스코드 기밀성 | 기밀성 |
| 인사, 회계 자료 기밀성 | 기밀성 |
| 고객 티켓 무결성(본사-지사 구간 엿보기, 변조) | 무결성 |
| 고객지원 포털 가용성 | 가용성 |
| 장비 설정 무결성(라우터 무단 접속) | 무결성 |

각 일차의 작업이 이 중 어느 요소와 연결되는지를 문서마다 적어 둔다.

## 면접 답변 틀

한 가지 기술을 설명할 때 아래 순서로 말하면 안정적이다.

1. 개념 한 줄: 이게 무엇인가
2. 왜 필요한가: 어떤 문제를 푸는가
3. 우리 구성에서: 어디에 어떻게 썼는가(실제 값)
4. 한계와 개선: 무엇이 부족하고 다음에 무엇을 할 것인가

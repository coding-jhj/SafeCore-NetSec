# 5일차 개념 정리: 동적 라우팅과 RIPv2

작업이 진행 중이다. 개념은 먼저 정리하고, 실습에서 확인한 내용은 "실습 관찰" 섹션에 추가한다.

## 1. 이 단계에서 하는 일
- 주 회선의 정적 경로를 지우고 본사와 지사 라우터에 RIPv2를 적용한다.
- 예비 시리얼 회선은 passive로 두고, 지사에 새 네트워크를 만들어 본사가 자동으로 학습하는지 확인한다.
- 사무실 쪽 포트를 passive로 하고 RIP이 켜진 포트에 인증을 설정한다.

## 2. 개념

### 정적 라우팅과 동적 라우팅
| 구분 | 정적 | 동적 |
|------|------|------|
| 경로 입력 | 관리자가 직접 | 라우터끼리 교환 |
| 네트워크 추가 | 양쪽에 수동 추가 | 선언만 추가하면 상대가 학습 |
| 장애 대응 | 인터페이스 down일 때만 | 광고가 끊기면 경로가 사라짐 |
| 부하 | 거의 없음 | 주기적 광고와 계산 필요 |
| 적합한 곳 | 작고 단순한 구간 | 네트워크가 늘어나는 구간 |

### 라우팅 프로토콜의 분류
- 같은 조직 내부에서 쓰는 IGP(RIP, OSPF, EIGRP)와 조직 사이에서 쓰는 EGP(BGP)로 나눈다.
- 계산 방식으로는 거리 벡터(RIP: 이웃이 알려준 경로와 거리를 믿음)와 링크 상태(OSPF: 전체 지도를 만들어 직접 계산)로 나눈다.

### RIP
- 거리 벡터 방식의 IGP다. metric은 홉 수(거치는 라우터 수)이고, 최대 15홉이며 16은 도달 불가를 뜻한다.
- 30초마다 자신의 라우팅 테이블 전체를 이웃에게 광고한다. UDP 520번을 쓴다.
- 기본 타이머: update 30초, invalid 180초(광고가 끊긴 경로를 무효로 표시), holddown 180초, flush 240초(테이블에서 삭제). 그래서 수렴이 느리다는 평가를 받는다.
- 기본 AD는 120이다.
- 한계: 홉 수만 보고 대역폭이나 지연은 고려하지 않는다. 15홉 제한이 있어 큰 네트워크에 맞지 않는다. 수렴이 느리다.

### RIPv1과 RIPv2
| 구분 | v1 | v2 |
|------|-----|-----|
| 서브넷 마스크 전달 | 안 함(클래스풀) | 함(클래스리스, VLSM 가능) |
| 광고 방식 | 브로드캐스트 | 멀티캐스트 224.0.0.9 |
| 인증 | 없음 | 지원(평문, MD5) |

### auto-summary
- 다른 클래스 대역을 지나갈 때 자동으로 클래스 경계로 요약하는 기능이다. 우리처럼 192.168.10.0, 192.168.80.0/30처럼 서로 다른 C클래스에 서브넷이 흩어진 구성에서는 문제를 일으킬 수 있어서 `no auto-summary`로 끈다.

### network 명령의 의미
- RIP의 `network` 명령은 라우터가 어느 인터페이스에서 RIP을 켤지, 어느 대역을 광고할지를 정한다. 이 명령은 클래스 기준으로 해석된다.
- 192.168.x.0은 C클래스라 대역마다 따로 선언해야 한다. `network 192.168.0.0` 하나로는 192.168.0.x 대역만 해당한다.
- 그래서 지사에 새 네트워크(예: 창고)가 생기면, 지사 라우터에 그 대역의 `network` 선언 하나만 추가하면 본사가 자동으로 학습한다. 이것이 "저절로 연결"의 핵심이다.

### passive-interface
- 해당 인터페이스로 RIP 광고를 내보내지 않게 하는 설정이다. 일반적으로 RIP에서 passive 인터페이스는 광고 송신만 막고, 수신은 처리한다.
- 왜 쓰나: 사무실 PC 쪽 인터페이스로 라우팅 정보를 내보낼 이유가 없다. 내보내면 불필요한 트래픽이고, PC에서 가짜 RIP 광고를 보내 경로를 오염시키는 공격의 통로가 될 수 있다. 예비 시리얼에 쓰는 것은 예비 회선을 4일차의 정적 floating route로만 쓰기 위해서다(우리의 설계 의도).

### RIPv2 인증
- 이웃 라우터가 맞는 키를 가지고 있을 때만 광고를 받아들이게 하는 기능이다. 허가되지 않은 라우터가 가짜 경로를 끼워 넣는 것을 막는다.
- 평문 인증은 비밀번호가 패킷에 그대로 실려서 캡처하면 보인다. MD5 인증은 해시로 보내서 비밀번호가 직접 보이지 않으므로 더 낫다. 설정은 key chain으로 키를 만들고 인터페이스에 적용한다.
- 인증을 한쪽에만 걸면 이웃 관계가 끊기므로 양쪽에 같이 설정해야 한다.

## 3. 우리 프로젝트의 값
- RIP을 켤 대역: 본사 192.168.10, 20, 30, 40, 50, 70, 80 / 지사 192.168.60, 70, 80
- passive 대상: 예비 시리얼(본사 Serial0/2/0, 지사 Serial0/3/0), 부서 LAN 쪽 인터페이스
- 인증 대상: 주 회선(본사 Vlan70, 지사 Gi0/1)

## 4. 실습 관찰 (진행에 따라 추가)
- 주 회선 정적 경로(AD 1)를 지우자 AD 250 예비 경로가 올라왔고 지사 ping 5/5가 성공했다. 왕복 시간이 삭제 전 이더넷 구간의 0 ms에서 2/20/39 ms(min/avg/max)로 늘어서, 트래픽이 시리얼 선으로 이동했음을 확인했다.
- `network 192.168.0.0` 한 줄만 입력했을 때: `show ip protocols`에 Routing for Networks 192.168.0.0만 있고 RIP이 동작하는 인터페이스 목록과 이웃 경로 출처가 비었으며, `show ip route`에 `R` 경로가 없었다. C클래스 대역은 192.168.10.0, 192.168.20.0처럼 대역마다 `network`를 따로 선언해야 RIP이 켜진다는 것을 직접 확인했다. 이때도 ping이 성공한 것은 RIP이 아니라 예비 정적 경로 덕분이어서, "ping이 된다"만으로는 RIP 동작을 증명할 수 없고 라우팅 테이블의 `R` 경로를 봐야 한다.
- 대역별 `network` 선언 후 RIP 적용 결과, passive 적용 결과, 새 네트워크 학습, 장애 전환, 인증 결과는 작업 후 추가한다.

## 5. 면접 예상 질문과 답변 요지
- 정적과 동적의 차이: 정적은 관리자가 입력하고, 동적은 라우터끼리 교환한다. 네트워크가 늘어나면 동적이 유리하다.
- 왜 RIP을 썼나: 수업에서 배운 가장 단순한 거리 벡터 프로토콜이라 동적 라우팅의 동작 원리를 확인하기 좋다. 한계(느린 수렴, 15홉)는 OSPF 같은 프로토콜로 개선할 수 있다.
- RIPv1과 v2의 차이: v2는 서브넷 마스크를 전달해 VLSM을 쓸 수 있고, 멀티캐스트를 쓰며, 인증을 지원한다.
- passive-interface를 왜 썼나: 사용자 PC 쪽으로 라우팅 정보를 내보낼 필요가 없고, 가짜 광고로 경로가 오염되는 것을 줄이기 위해서다.
- 라우팅 인증은 왜 필요한가: 허가되지 않은 라우터가 가짜 경로를 광고해 트래픽을 끌어가는 것을 막기 위해서다. 가능하면 평문이 아니라 MD5를 쓴다.
- 정적 예비 경로와 RIP이 같이 있을 때 어떻게 동작하나: AD가 RIP 120, 정적 예비 250이라서 RIP이 살아 있으면 RIP을 쓰고, RIP 경로가 사라지면 예비 정적 경로가 올라온다.

## 6. 보안 요소와의 연결
- 라우팅 인증과 passive-interface는 장비 설정과 경로의 무결성을 지키는 조치다. 가짜 라우터가 경로를 끼워 넣어 트래픽을 우회시키거나 엿보는 공격을 줄이는 것이 목적이다.
- 동적 라우팅과 예비 경로는 가용성을 높인다.

# 6일차 이어서 하기 (작업 메모)

6일차를 끝내면 이 파일은 삭제한다. 결과 기록의 본문은 [6일차 학습문서](6일차_학습문서.md)이고, 이 파일은 남은 순서와 명령을 모아 둔 메모다.

## 0. 여기까지 (2026-11-22)

- 브랜치 `ospf`. 단계 0~7 완료, 단계 8-1 중이다.
- 주 회선(Vlan70 구간)에는 인터페이스 방식 MD5가 양쪽에 적용되어 있다(이웃 FULL, `O` 경로 확인).
- **시리얼 구간에는 아직 인증이 없다.**
- OSPF 설정, `passive-interface default`(이웃 구간만 열림)는 적용되어 있다.
- 키 값은 문서에 쓰지 않는다. 아래에서 `<키>`는 직접 정한 값으로 바꿔 입력한다. 시리얼 구간 키는 주 회선 키와 같아도 되고 달라도 된다(인터페이스마다 따로 설정하는 값이다).

## 1. 시작하기

1. 저장소를 받고 브랜치를 전환한다.
```

git switch ospf
```
2. `00_구축결과/SafeCoreNetSec.pkt`를 연다.
3. Claude를 새로 시작하는 경우 첫 메시지로 아래를 붙여넣는다(같은 컴퓨터면 "6일차 이어서"만 말해도 된다).

> SafeCore 프로젝트 6일차를 이어서 진행해줘. ospf 브랜치를 pull 했고, 04_학습문서/6일차_이어서하기_작업메모.md와 6일차_학습문서.md 맨 끝을 읽고 단계 8-1 시리얼 구간부터 하면 돼. 한 단계씩 장비별 전체 명령 블록을 알려주고, 결과는 학습 문서에 바로 기록해줘.

4. 파일을 연 뒤 몇 분 기다리면 OSPF가 다시 수렴한다. 아래를 확인한다.

**SC-BR-R1**
```
show ip ospf neighbor
show ip route ospf
```
**SC-HQ-R1**
```
show ip ospf neighbor
show ip route ospf
```
- 양쪽 모두 이웃이 시리얼 `FULL/  -`와 주 회선 FULL 두 줄이어야 하고, 지사에 `O` 경로 6줄(`192.168.10`~`50.0`, `192.168.255.1`), 본사에 `O` 경로 3줄(`192.168.60.0`, `192.168.90.32/27`, `192.168.255.2`)이 있어야 한다.
- 지사 경로가 비어 있으면 단계 5에서 겪은 증상이다. 지사에서 `clear ip ospf process`를 입력하고 프롬프트 `Reset ALL OSPF processes? [no]:`에 **`yes`를 직접 입력**한다. 엔터만 치면 `no`로 처리되어 초기화되지 않는다. 그래도 안 되면 `show ip ospf database`에서 LSA 3개(라우터 2, 네트워크 1)가 있는지 본다.

## 2. 단계 8-1. 시리얼 구간 인터페이스 방식 MD5

**2-1. 변경 전 기준 (지사)**

**SC-BR-R1**
```
show ip ospf neighbor
```

**2-2. 본사만 먼저 설정**

**SC-HQ-R1**
```
configure terminal
interface serial 0/2/0
ip ospf authentication message-digest
ip ospf message-digest-key 1 md5 <키>
end
```

**2-3. 약 45~60초 뒤 끊김 확인 (이번에는 출력을 꼭 남긴다)**

**SC-BR-R1**
```
show ip ospf neighbor
show ip route ospf
```
**SC-HQ-R1**
```
show ip ospf neighbor
```
- 시리얼 이웃이 사라지고 주 회선 줄만 남는 것으로 예상한다(예상이며 아직 확인하지 않았다). 주 회선은 이미 인증이 맞아 있으므로 경로는 `via 192.168.70.1` 그대로여야 한다.
- 주 회선(Vlan70) 구간에서는 본사만 먼저 설정한 직후의 끊김을 기록하지 못했다. 이 구간에서 확인한 결과를 학습 문서 8-1에 같이 적는다.

**2-4. 지사 설정**

**SC-BR-R1**
```
configure terminal
interface serial 0/3/0
ip ospf authentication message-digest
ip ospf message-digest-key 1 md5 <키>
end
```

**2-5. 30~50초 뒤 복구 확인**

**SC-BR-R1**
```
show ip ospf neighbor
show ip ospf interface serial 0/3/0
```
- 시리얼 이웃이 `FULL/  -`로 돌아오고, `show ip ospf interface`에 `Message digest authentication enabled`와 `Youngest key id is 1`이 나와야 한다. 키 값이 출력에 보이면 그 줄은 지우고 기록한다.

## 3. 단계 8-2. 인터페이스 설정 취소

구간마다 본사만 먼저 취소해서 끊기는 것을 보고, 지사를 취소해서 복구되는지 본다. `no ip ospf message-digest-key 1`이 이 Packet Tracer에서 거부되면 그 결과를 기록한다(미확인).

**3-1. 주 회선 구간, 본사 먼저**

**SC-HQ-R1**
```
configure terminal
interface vlan 70
no ip ospf authentication message-digest
no ip ospf message-digest-key 1
end
```
45~60초 뒤 **SC-BR-R1**에서 `show ip ospf neighbor`, `show ip route ospf`로 주 회선 이웃이 사라지는지 본다(시리얼은 아직 인증이 있어 유지된다).

**SC-BR-R1**
```
configure terminal
interface gigabitethernet 0/1
no ip ospf authentication message-digest
no ip ospf message-digest-key 1
end
```
30~50초 뒤 `show ip ospf neighbor`로 주 회선 이웃이 FULL로 돌아오는지 본다.

**3-2. 시리얼 구간, 본사 먼저**

**SC-HQ-R1**
```
configure terminal
interface serial 0/2/0
no ip ospf authentication message-digest
no ip ospf message-digest-key 1
end
```
45~60초 뒤 **SC-BR-R1**에서 `show ip ospf neighbor`로 시리얼 이웃이 사라지는지 본다.

**SC-BR-R1**
```
configure terminal
interface serial 0/3/0
no ip ospf authentication message-digest
no ip ospf message-digest-key 1
end
```
30~50초 뒤 `show ip ospf neighbor`가 FULL 두 줄로 돌아오고, `show ip ospf`의 `Area has no authentication`이 나오는지 확인한다.

## 4. 단계 8-3. area 방식

area 방식은 area 0의 모든 인터페이스에 인증을 한꺼번에 요구한다. 키는 여전히 인터페이스마다 설정한다. 이 Packet Tracer가 `area 0 authentication message-digest`를 지원하는지는 미확인이다. 명령이 거부되거나 `show ip ospf`에 반영되지 않으면 그대로 "미지원"으로 기록한다.

**4-1. 본사만 먼저**

**SC-HQ-R1**
```
configure terminal
router ospf 1
area 0 authentication message-digest
exit
interface vlan 70
ip ospf message-digest-key 1 md5 <키>
exit
interface serial 0/2/0
ip ospf message-digest-key 1 md5 <키>
end
```
45~60초 뒤 **SC-BR-R1**에서 `show ip ospf neighbor`, `show ip route ospf`를 본다.
- 인터페이스 방식과 달리 두 구간(주 회선과 시리얼)이 **한꺼번에** 끊기는지 확인한다(예상이며 미확인). 둘 다 끊기면 지사는 `O` 경로가 모두 사라진다.

**4-2. 지사 설정**

**SC-BR-R1**
```
configure terminal
router ospf 1
area 0 authentication message-digest
exit
interface gigabitethernet 0/1
ip ospf message-digest-key 1 md5 <키>
exit
interface serial 0/3/0
ip ospf message-digest-key 1 md5 <키>
end
```
30~50초 뒤 **SC-BR-R1**과 **SC-HQ-R1**에서 확인한다.
```
show ip ospf neighbor
show ip route ospf
show ip ospf
```
- 이웃 두 줄이 FULL로 돌아오고, `show ip ospf`의 `Area BACKBONE(0)` 아래에 메시지 다이제스트 인증이 표시되는지 본다(출력 형식은 미확인).

## 5. 단계 8-4. 최종 상태 결정

- 비교 항목: 끊김이 구간별(인터페이스 방식)인지 한꺼번에(area 방식)인지, 설정 줄 수, 새 인터페이스를 추가했을 때 자동으로 인증이 요구되는지(area 방식의 장점), 구간마다 키를 다르게 줄 수 있는지(인터페이스 방식의 장점).
- 권장은 **인터페이스 방식을 최종으로 둔다**: 계획서 6일차 서술(구간마다 설정)과 일치하고, 구간마다 키를 달리할 수 있다. 최종 상태를 정하면 사용자와 확인한 뒤 맞춘다.
- area 방식을 지우려면 양쪽 `router ospf 1` 안에서 `no area 0 authentication message-digest`를 입력한다(이 명령이 되는지는 미확인).
- 최종 상태를 정한 뒤 양쪽 `write memory`와 Packet Tracer 저장(Ctrl+S)을 한다.

## 7. 작업 규칙

- 한 단계씩, 장비별 전체 명령 블록과 확인 명령, 읽을 포인트를 안내하고, 결과는 학습 문서에 바로 기록한다.
- `|` 필터는 한 패턴만 쓴다. 인터페이스 이름은 `show ip interface brief` 출력 그대로 쓴다(본사: `Vlan70`, `Serial0/2/0`, 지사: `GigabitEthernet0/1`, `Serial0/3/0`).
- 못 한 것은 "미검증" 또는 "미확인"으로 적는다. 장비 설정은 8-4 결정 전까지 `write memory`를 하지 않는다.
- 학습 문서에 물결표와 한자를 쓰지 않는다.

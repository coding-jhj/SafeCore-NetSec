# 5일차 명령어 로그

- 날짜: 2026-11-21
- 작업 중 입력한 명령어를 순서대로 기록. 작업 끝나면 5일차_작업계획서.md "결과" 섹션에 요약 반영.
- 범위: 본사-지사 경로를 정적 라우팅에서 RIPv2로 전환 (강사 작업 6개 + 심화).
- 강사 작업: (1) 주 회선 정적 경로 삭제(예비 유지) (2) 두 라우터 RIPv2 (3) 예비 회선 passive (4) 지사에 창고 네트워크 추가 후 동적 라우팅 확인 (5) 장애 실습 후 예비 경로 /24 (6) 사무실 쪽 포트 passive + RIP 포트 인증.

## 1. 주 회선 정적 경로 삭제 (예비 경로 AD 250은 유지)

삭제 전 확인: 설정에 예비 경로가 실제로 들어 있는지, 삭제 전 연결 상태.

### SC-HQ-R1 (본사 라우터)
```
show running-config | include ip route
show ip route
```

### SC-BR-R1 (지사 라우터)
```
show running-config | include ip route
show ip route
ping 192.168.10.1
```

삭제 전 확인 결과:
- SC-HQ-R1 `show running-config | include ip route`: `ip route 192.168.60.0 255.255.255.0 192.168.70.2`(AD 1), `ip route 192.168.60.0 255.255.255.0 192.168.80.2 250`(예비).
- SC-BR-R1 `show running-config | include ip route`: 192.168.10.0, 20.0, 30.0, 40.0, 50.0 대역 각각 `192.168.70.1`(AD 1) 5줄과 `192.168.80.1 250`(예비) 5줄. 예비 경로는 전부 마스크 255.255.255.0이라 이미 /24.
- `show ip route`: 양쪽 모두 AD 1 정적 경로만 라우팅 테이블에 올라와 있고 예비 경로는 대기 상태. 192.168.80.0/30(Serial)도 connected로 올라와 있음.
- SC-BR-R1 `ping 192.168.10.1`: 80 percent(4/5), 첫 패킷만 유실(ARP 학습 과정으로 추정), 이후 4개 성공.

캡처(삭제 전 정적 라우팅 상태, 결과 문서용):
- `99_첨부파일/5일차_1_정적라우팅_본사_변경전.png`: SC-HQ-R1 `show ip route static`
- `99_첨부파일/5일차_2_정적라우팅_지사_변경전.png`: SC-BR-R1 `show ip route static`

삭제: next-hop(192.168.70.x)까지 정확히 적어야 AD 1 경로만 지워지고 192.168.80.x AD 250 예비 경로는 남는다.

### SC-HQ-R1 (본사 라우터)
```
configure terminal
no ip route 192.168.60.0 255.255.255.0 192.168.70.2
exit
```

### SC-BR-R1 (지사 라우터)
```
configure terminal
no ip route 192.168.10.0 255.255.255.0 192.168.70.1
no ip route 192.168.20.0 255.255.255.0 192.168.70.1
no ip route 192.168.30.0 255.255.255.0 192.168.70.1
no ip route 192.168.40.0 255.255.255.0 192.168.70.1
no ip route 192.168.50.0 255.255.255.0 192.168.70.1
exit
```

삭제 후 확인: 양쪽 `show ip route static`, `show running-config | include ip route`, 지사에서 `ping 192.168.10.1`.

결과:
- SC-HQ-R1 `show ip route static`: `S 192.168.60.0/24 [250/0] via 192.168.80.2`
- SC-BR-R1 `show ip route static`: 192.168.10.0, 20.0, 30.0, 40.0, 50.0 대역 5줄 전부 `[250/0] via 192.168.80.1`
- AD 1 경로가 지워지고 예비 경로(AD 250)가 라우팅 테이블에 올라옴. 트래픽이 시리얼 백업 선으로 이동.
- SC-BR-R1 `ping 192.168.10.1`: 100 percent(5/5), round-trip min/avg/max = 2/20/39 ms. 삭제 전 이더넷 구간(0/0/0 ms)보다 느려진 것은 시리얼 선을 타고 있기 때문.

## 2. 두 라우터에 RIPv2 설정

RIP의 `network` 명령은 클래스 기준이다. 192.168.x.0은 C클래스라 대역마다 따로 선언해야 하고, `network 192.168.0.0` 하나로는 192.168.0.x 대역만 켜진다(정정: 처음에 이 명령 하나로 192.168.x.x 전체가 켜진다고 잘못 안내했고, 그 명령을 한 번 입력한 뒤 아래처럼 정정함). 이 단계에서는 부서 LAN, 주 회선, 예비 시리얼 대역을 전부 선언해서 RIP이 예비 시리얼로도 나가는 것을 먼저 관찰하고, 3단계에서 passive로 막는다.

정정 전 입력: 양쪽 라우터에서 `router rip`, `version 2`, `no auto-summary`, `network 192.168.0.0`.

정정 전 확인 결과(예상대로 RIP이 동작하지 않음):
- 양쪽 `show ip protocols`: `Routing for Networks: 192.168.0.0`만 있고, Interface Send/Recv 목록이 비어 있으며 Routing Information Sources도 비어 있음. version 2 송수신, auto-summary 꺼짐, 타이머 30/180/180/240은 정상 표시.
- 양쪽 `show ip route`: `R` 경로 없음. 본사 `S 192.168.60.0/24 [250/0] via 192.168.80.2`, 지사 `S 192.168.10~50.0/24 [250/0] via 192.168.80.1`(5줄)이 그대로 사용됨.
- SC-BR-R1 `ping 192.168.10.1`: 5/5 성공, 1/7/13 ms. 통신은 RIP이 아니라 예비 정적 경로(시리얼)로 이뤄진 것.
- 결론: 192.168.10.0, 20.0 등 대역마다 `network`를 따로 선언해야 RIP이 해당 인터페이스에서 켜진다.

### SC-HQ-R1 (본사 라우터)
```
configure terminal
router rip
version 2
no auto-summary
no network 192.168.0.0
network 192.168.10.0
network 192.168.20.0
network 192.168.30.0
network 192.168.40.0
network 192.168.50.0
network 192.168.70.0
network 192.168.80.0
exit
exit
```

### SC-BR-R1 (지사 라우터)
```
configure terminal
router rip
version 2
no auto-summary
no network 192.168.0.0
network 192.168.60.0
network 192.168.70.0
network 192.168.80.0
exit
exit
```

확인 (결과 대기 중): 양쪽 `show ip protocols`, `show ip route`, 지사에서 `ping 192.168.10.1`.
